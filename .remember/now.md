## T4 0e44d83e recursive-halving/doubling DDA (RHD) — COMPLETE (2026-07-07)
- LESSON (CRITICAL for any DDA/IPC feature): DDA IPC paths (RHD, dda_all_reduce, dda_reduce_scatter, etc.) are SKIPPED when comm is in directMode. ncclTransportCheckP2pType sets directMode=1 whenever two local ranks share a pid — i.e. any single-process `rccl-tests -g 8` run. ncclDdaIpcCommInit then skips scratch/barrier alloc, so gate-on == gate-off (both fall back to ring). To honestly measure ANY DDA feature you MUST run 1 process per GPU: build rccl-tests with `make MPI=1 NAME_SUFFIX=_mpi GPU_TARGETS=gfx950 MPI_HOME=/usr/lib/x86_64-linux-gnu NCCL_HOME=<rccl>/build/release CUSTOM_RCCL_LIB=<same>` then `mpirun -np 8 <coll>_perf_mpi -g 1`. Verify engagement via NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=COLL,INIT -> expect "RCCL RHD ..." on all 8 ranks and "directMode 0".
- SETUP: libopenmpi-dev was not installed; `sudo apt-get install -y libopenmpi-dev` (passwordless sudo available). Headers land at /usr/lib/x86_64-linux-gnu/openmpi/include/mpi.h, libs at .../openmpi/lib — matches rccl-tests src/Makefile MPI paths.
- RESULT (honest, negative): RHD is bit-exact (#wrong==0, fp32/fp16/bf16) but ~5-6x SLOWER than ring/tree on 8xMI355X XGMI clique across 256K-64M (AR 64M 379->61 GB/s, RS 361->61). Cause: full XGMI clique is bandwidth-bound not latency-bound, so RHD's fewer-rounds bet doesn't pay; extra IPC-scratch copy + fine-grained IPC round-trips dominate. Left default-off (RCCL_RHD_ENABLE=0), NOT force-enabled. Report: projects/rccl/perf_results/T4_rhd.md; raw MPI sweeps in perf_results/t4/mpi_*.txt. Single-process t4/{ar,rs}_{off,on}.txt are stale (RHD never engaged).
- Enum: RCCL_RECURSIVE_HALVING added at rccl_common.h:63 (after RCCL_SYMMETRIC, before RCCL_ALGO_COUNT) — RCCL-local, doesn't perturb NCCL enum. tuning.cc latCount term is gated on ncclRhdEnabled() so it's a no-op when off.
