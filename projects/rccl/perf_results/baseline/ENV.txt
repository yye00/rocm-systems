size-range note: The AC-named command uses -e 8G. This build host is a SHARED node: an
                 external root-owned inference server (vLLM serving DeepSeek-V4-Flash,
                 --gpu-memory-utilization 0.97) permanently occupies ~295 GB of one GPU's
                 309 GB HBM, leaving only ~14.2 GB free on that device. rccl-tests allocates
                 ~3x the message size per rank (sendbuff + recvbuff + correctness-check
                 buffer), so -e 8G and -e 4G OOM on the occupied GPU ('HIP failure: out of
                 memory'), while -e 2G succeeds cleanly on all 8 GPUs. The baseline is
                 therefore captured over the full feasible range 8 B .. 2 GiB (factor-2
                 steps). This is the correct matched BEFORE: every AFTER A/B measurement
                 runs on this same shared host under the same memory ceiling, so the
                 before/after comparison stays apples-to-apples. The external server was NOT
                 killed (it is another tenant's production workload). Re-running -e 8G on a
                 dedicated/idle gfx950 node would extend the curve to 8 GiB unchanged.

topo_expl fix  : topo_expl's XML loader (tools/topo_expl/src/topo_expl_impl.cpp,
                 ncclTopoGetSystem) did not reset the cpu host_hash after reading a model
                 XML, unlike real RCCL (src/graph/topo.cc). The gfx950 fixture
                 (models/topo_8p_950.xml) preserves a real non-zero host_hash, which made the
                 localHostHash=0 lookup fail at the second NUMA node ('Failed to create
                 topology explorer context'). Fixed by zeroing every cpu node's host_hash in
                 the loader, matching upstream behavior and the 58 fixtures that omit it.
